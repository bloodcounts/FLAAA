# FLAAA Platform Services

This directory contains the Docker Compose configuration for running the FLAAA (Federated Learning with Authentication, Authorization and Accounting) platform services.

## Overview

The platform consists of the following services:

- **PDP (Policy Decision Point)**: A Node.js XACML 3.0 policy decision service (Pino-logged, JWS-signed audit trail)
- **SuperLink**: A customised Flower SuperLink with Policy Enforcement Point (PEP) integration and gRPC TLS
- **cert-init** *(SSL compose only)*: One-shot Alpine container that generates EC P-256 certificates if not present
- **node-registration** *(SSL compose only)*: One-shot container that generates node keypairs, registers them with SuperLink, and updates the PDP node registry

## Architecture

```
FL Node ──[gRPC + TLS]──▶ SuperLink Fleet API (9092)
FL Node ──[gRPC + TLS]──▶ SuperLink Control API (9093)
flwr CLI ──[gRPC + TLS]──▶ SuperLink Control API (9093)
                               │
                         [HTTP, internal Docker net]
                               │
                              PDP (8080)
                         XACML 3.0 decisions
                         JWS-signed audit log
```

### Service Ports

| Port | Service | Protocol |
|------|---------|----------|
| 8080 | PDP `/getDecision`, `/health`, `/api-docs` | HTTP |
| 9091 | SuperLink ServerAppIo API | gRPC (insecure, localhost-only) |
| 9092 | SuperLink Fleet API | gRPC + TLS |
| 9093 | SuperLink Control API | gRPC + TLS |

## Compose Files

| File | Purpose |
|------|---------|
| `docker-compose.tls.platform.yml` | **Recommended** — SSL/TLS enabled, auto cert generation, node registration |
| `docker-compose.platform.yml` | Plain HTTP/insecure — useful for local development without TLS |

## Quick Start (TLS — Recommended)

### Prerequisites

- Docker and Docker Compose v2.1+
- `openssl` (for local cert generation outside Docker)
- Ports 8080, 9091, 9092, 9093 available

### First Run

```bash
# Generates certificates, starts all services, registers nodes
docker compose -f docker-compose.tls.platform.yml up --build
```

On first run the `cert-init` service generates certificates into `./certificates/` and `./pdp/certs/`. Subsequent runs skip generation if `certificates/ca.crt` already exists.

### Stop

```bash
# Stop services
docker compose -f docker-compose.tls.platform.yml down

# Stop and remove volumes (resets SuperLink state)
docker compose -f docker-compose.tls.platform.yml down -v
```

### Re-run Node Registration

The node-registration service runs once per `up` and then exits. To re-register without full teardown:

```bash
docker compose -f docker-compose.tls.platform.yml run --rm node-registration
```

## Certificates

Certificates are generated by `scripts/generate_certs.sh` (EC P-256 / `prime256v1` throughout):

| File | Purpose |
|------|---------|
| `certificates/ca.crt` | Self-signed CA certificate |
| `certificates/ca.key` | CA private key |
| `certificates/server.crt` / `.pem` | SuperLink TLS certificate (signed by CA, includes SANs for `localhost` and `superlink`) |
| `certificates/server.key` | SuperLink TLS private key |
| `pdp/certs/pdp_sign_key.pem` | PDP JWS signing key (EC P-256, ES256) |
| `pdp/certs/pdp_sign_pub.pem` | PDP JWS public key (for audit log verification) |

All cert directories are in `.gitignore` — private keys are never committed.

To regenerate certificates manually:

```bash
rm -rf certificates/ pdp/certs/
bash scripts/generate_certs.sh
```

## Services

### PDP Service

- **Port**: 8080
- **Health Check**: `GET /health`
- **Decision Endpoint**: `GET /getDecision`
- **API Docs**: `GET /api-docs`
- **Logs**: Mounted to `./pdp/logs` (rolling Pino JSON logs)
- **Environment**:
  - `PDP_PORT=8080`
  - `LOG_LEVEL=info`
  - `NODE_ENV=production`

### SuperLink Service

- **Ports**: 9092 (Fleet API, TLS), 9093 (Control API, TLS), 9091 (ServerAppIo, insecure)
- **Certs**: Mounted from `./certificates/` at `/app/certificates/`
- **Data Volume**: `superlink-data` (persists Flower state)
- **Environment**:
  - `PDP_DECISION_URL=http://pdp:8080/getDecision`
- **Dependencies**: Waits for `cert-init` to complete and `pdp` to be healthy

### cert-init Service

- Runs `scripts/generate_certs.sh` only if `certificates/ca.crt` is absent
- Exits with code 0; `pdp` and `superlink` wait on `condition: service_completed_successfully`

### node-registration Service

- Generates 5 EC node keypairs into `./superlink-data/`
- Derives deterministic node IDs from public key hashes
- Registers nodes with SuperLink via `flwr supernode register` (gRPC + TLS)
- Updates `pdp/sample_data/nodes.json` with node IDs for policy evaluation

## Testing

### PDP Health and Decisions

```bash
# Health
curl http://localhost:8080/health

# Task approval
curl "http://localhost:8080/getDecision?action=task_approval&task_id=medical"

# Membership validation
curl "http://localhost:8080/getDecision?action=membership_validation&task_id=medical&node_id=<node_id>"

# Train permission (registered node — expect Permit)
curl "http://localhost:8080/getDecision?action=train&task_id=medical&node_id=<node_id>"

# Train permission (unregistered node — expect Deny)
curl "http://localhost:8080/getDecision?action=train&task_id=medical&node_id=9999999"
```

Use node IDs from `pdp/sample_data/node_ids.json` for registered node tests.

### SuperLink gRPC (TLS)

```bash
# List Fleet service methods (verified TLS)
grpcurl -cacert certificates/ca.crt localhost:9092 list flwr.proto.Fleet

# List registered nodes via Control API
grpcurl -cacert certificates/ca.crt localhost:9093 flwr.proto.Control/ListNodes

# Confirm TLS is active (should fail)
grpcurl -plaintext localhost:9092 list
```

### PDP Conformance Tests (XACML policy suite)

```bash
cd pdp && npm run conformance
```

### End-to-End: Connect a SuperNode

```bash
flwr supernode \
  --superlink localhost:9092 \
  --root-certificates certificates/ca.crt \
  --auth-supernode-private-key superlink-data/node1/node1.pem \
  --auth-supernode-public-key superlink-data/node1/node1.pub
```

The PEP in the `CustomFleetServicer` will call the PDP and return allow/deny based on the node's registration status.

## Development

### Build and Restart

```bash
# Rebuild all images
docker compose -f docker-compose.tls.platform.yml up --build

# Rebuild a specific service
docker compose -f docker-compose.tls.platform.yml build pdp
```

### Shell Access

```bash
docker compose -f docker-compose.tls.platform.yml exec pdp sh
docker compose -f docker-compose.tls.platform.yml exec superlink bash
```

### Insecure Compose (no TLS, no cert generation)

```bash
docker compose -f docker-compose.platform.yml up --build
# SuperLink runs in INSECURE mode; use grpcurl -plaintext localhost:9092
```

### Flower CLI Config

`examples/flwr-config.toml` is pre-configured for the `cancer-detection` federation connecting to `superlink:9093` with TLS. It is bind-mounted into the `node-registration` container at `~/.flwr/config.toml`.

## Troubleshooting

### Port Conflicts

```bash
lsof -i :8080
lsof -i :9092
```

### Certificate Issues

```bash
# Inspect the server cert SANs
openssl x509 -in certificates/server.crt -text -noout | grep -A2 "Subject Alternative"

# Verify chain
openssl verify -CAfile certificates/ca.crt certificates/server.crt

# Force cert regeneration
rm -rf certificates/ && docker compose -f docker-compose.tls.platform.yml up
```

### Service Won't Start

```bash
docker compose -f docker-compose.tls.platform.yml logs cert-init
docker compose -f docker-compose.tls.platform.yml logs pdp
docker compose -f docker-compose.tls.platform.yml logs superlink
```

### Data Persistence

```bash
# List volumes
docker volume ls | grep flaaa

# Reset SuperLink state
docker compose -f docker-compose.tls.platform.yml down -v
```
